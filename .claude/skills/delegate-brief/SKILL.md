# 委任ブリーフの型

**どの役に投げるかは `agent-routing` スキル。** ここは「投げるときに何を書くか」。

委任の失敗はほぼ全部**ブリーフの穴**から出る。曖昧な依頼は、エージェントが善意で埋めた結果として想定外の差分になって返ってくる。

## 必ず書く6項目

| 項目 | 書かないとどうなるか |
|---|---|
| **① 目的**（何のため・なぜ今） | 指示の字面だけ満たして目的を外す |
| **② 成果物**（どのファイルを作る/直すか） | 想定外の場所に書かれる |
| **③ 触ってよい範囲**（このファイルのみ、等） | 関係ないファイルまで「ついでに」直される |
| **④ 完了条件**（何が緑なら終わりか） | 自己判断で早く切り上げる／延々やり続ける |
| **⑤ 制約**（規約・やってはいけないこと） | 規約違反の差分をレビューで差し戻し |
| **⑥ 報告してほしいこと** | 何が分かったかが失われる |

### 雛形

```
（背景）Issue #N の一環で、○○を実現したい。ブランチは feature/xxx（作成済み・checkout 済み）。

## やること
- 成果物：<パス>

## 調査/実装してほしいこと
1. …
2. …

## 制約
- 触ってよいのは <パス> のみ。他ファイルは変更しない。
- <規約>
- 日本語で書く。
- 終わったら `scripts/ai-commit.sh -m "…"` でコミットする。

## 報告
<作ったもの>・<実測値>・調査で分かった非自明な点を報告してください。
```

## 並列で走らせるとき

**同一ブランチで複数エージェントを同時に動かす場合、担当ファイルを重ならないよう割り、そのことを各ブリーフに明記する。**

> **他のエージェントが同じブランチで別ファイルを作業中なので、このファイル以外は絶対に触らないこと。**

これが無いと、片方が `git add -A` や整形で相手の作業中ファイルを巻き込む。コミットも**自分が触ったファイルだけ**を指定させる。

ファイルが本質的に競合する（同じファイルを両方が直す）なら、並列にせず**直列に回すか worktree で隔離**する。

## 裁量の境界を書く

エージェントは判断を求められると止まるか、勝手に決める。**どちらをしてほしいかを先に書く。**

- 「規模が想定を超えたら**実行せず司令塔に確認**」
- 「命名は任せる。迷ったら既存の `xxx` に倣う」
- 「Issue 作成・push・PR は**しない**」（破壊的/外部公開の操作は本人判断）

## 役ごとの追記事項

| 役 | ブリーフに足すこと |
|---|---|
| **test-author** | 受け入れ条件を具体的に。**Red（失敗する）状態で止める**こと。実装は書かない |
| **coder** | **`*.test.*` は編集しない**（test-author の仕様テストが正本。不備は司令塔に申告）。緑にする最小実装 |
| **content-author** | 語数・レベル・テーマ。`npm run validate` 緑まで |
| **監査役**（ui-auditor / ddd-auditor / bug-watcher / pwa-verifier / reviewer） | **コードは変更しない**。指摘は `file:line` ＋根拠つきで |

## 受け取ったら検証する

**報告を鵜呑みにしない。** エージェントの報告は「やったつもり」を含む。安いものから確かめる：

```bash
git log origin/develop..HEAD --oneline     # 本当にコミットされたか
git show --stat HEAD                       # 触った範囲は約束どおりか
```

- **表やパスを書かせたなら実在確認**（`ls` / `Read`）。存在しないファイル名がもっともらしく載ることがある
- **「動く」と書かれたら実際に回す**（`npm run check:fast` 等）
- **数値を報告させたなら自分でも1つ2つ再現**する

差分が `*.test.*` に及んでいないか（coder の場合）も司令塔の確認事項。

## ブリーフが長くなるのは正しい

依頼文のトークンより、**穴のある依頼で手戻りするコストの方がはるかに高い**。制約と完了条件は削らない。逆に、背景の長い説明は要らない（必要なら「`xxx` スキルを読め」で足りる）。

---

台帳（`tmp/agent-status.tsv`）は**各エージェントが自己更新**する。ブリーフに書く必要は無い（→ `agent-routing` スキル）。
